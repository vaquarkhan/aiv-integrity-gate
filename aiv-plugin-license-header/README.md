# Module: `aiv-plugin-license-header` (gate `license-header`)

This opt-in gate checks that newly added source files carry one of the project's approved license/header markers. It is generic: projects define their own markers; the shipped ASF preset is one example.

## Architecture role

Default-off hard policy gate. It checks only added files because modified-file/whole-tree license compliance belongs to established tools such as RAT or organization scanners.

## Runtime flow

1. Select newly added configured source extensions.
2. Skip globally/gate-excluded paths.
3. Skip blank files and known generated suffixes.
4. Read the first 4,096 characters.
5. Skip files carrying a configured generated marker.
6. Pass when any approved header marker is present.
7. Emit a missing-header finding otherwise.

## Configuration

```yaml
gates:
  - id: license-header
    enabled: true
    severity: fail
    config:
      header_markers:
        - "SPDX-License-Identifier: Apache-2.0"
        - "Copyright 2026 Example Corp"
      generated_markers:
        - "DO NOT EDIT"
        - "Generated by"
      file_extensions: [.java, .py, .js, .ts]
      exclude_paths: [vendor/**]
```

`languages` aliases extension configuration. Supplying `header_markers` replaces defaults, allowing any licensing policy.

## Example

```java
// SPDX-License-Identifier: Apache-2.0
package example;
```

passes when that marker is approved. A new source file without an approved marker produces a structured finding at line 1.

## Failure behavior

Missing required header blocks by default. `severity: warn` supports rollout. Modified files, generated artifacts, blank files, and excluded paths are intentionally not findings.

## Trust

Header/generated/exclusion lists are policy and must live in protected `.aiv/config.yaml`. Strict runs consume the immutable base-ref snapshot so a PR cannot add a convenient marker/exclusion while being judged.

## Interactions

Use this gate as a changed-file first check, then a whole-tree license scanner through `external`. SARIF/Checks expose file-level findings. Proposal/document license concerns are separate.

## Extension points

Add generated suffixes/markers only with counterexample tests. Keep matching deterministic and bounded to the file head. Complex notice validation belongs in a dedicated analyzer folded through SARIF.

## Tests and build

`LicenseHeaderGateTest` and configuration tests cover added/modified files, markers, generated/blank/excluded files, extensions, custom policies, findings, and registration.

```bash
mvn -pl aiv-plugin-license-header test
mvn -pl aiv-plugin-license-header verify
```

## Boundary

Marker presence is not a complete legal/license audit. The gate does not identify third-party code, validate NOTICE contents, or determine compatibility. It enforces the configured new-file header invariant.
