# Airflow AIV benchmark — methodology

## What we measure

| Label class | Meaning | Hard-fail expected? | Use in metrics |
|-------------|---------|---------------------|----------------|
| `synthetic_positive` | Local fixture with objective AI/conflict markers | Yes | TP / FN |
| `objective_slop` | Real PR whose **file patches** contain verified AIV hard markers | Yes | TP / FN |
| `synthetic_negative` | Clean local fixture | No | TN / FP |
| `merged_control` | Merged Airflow PR, no verified markers in patch | No | TN / FP |
| `closed_unmerged_sample` | Closed unmerged PR, **no** verified markers | No | Flag-rate only — **not** AI-slop ground truth |

## What we do **not** claim

- Closed-unmerged ≠ AI-generated. AIP-120 counts volume/outcome, not model provenance.
- GitHub issue search for phrases like `Generated by ChatGPT` or `<<<<<<< SEARCH` is **unusable** as labeling (spot-checks show title/body false positives with **empty** patch hits).
- A CI-savings percentage requires a larger labeled true-positive set than markers alone currently provide on Airflow.

## Discovery procedure

```bash
python benchmarks/airflow/scripts/run-e2e-benchmark.py discover \
  --repo apache/airflow \
  --window 2026-06-20..2026-09-18 \
  --closed-limit 35 \
  --merged-limit 12
```

For each PR, `GET /repos/{repo}/pulls/{n}/files` patches are scanned for:

- merge conflict line markers
- `<<<<<<< SEARCH` / `>>>>>>> REPLACE`
- AI elision / assistant chatter / `YOUR_CODE_HERE`
- attribution strings (`Generated by ChatGPT`, etc.)

## Materialization note

Each PR is scored in a **mini git workspace**. Changed files are loaded from the GitHub Contents API at the PR **head SHA** (full file text). Patch-only reconstruction is a fallback and can create false syntax failures — prefer head contents for published reports.


```bash
mvn -pl aiv-cli -am package -DskipTests
python benchmarks/airflow/scripts/run-e2e-benchmark.py run
```

Each case is materialized as a **tiny git repo** (PR patches applied as files + `.aiv/` from this folder). `aiv-cli` runs with `--output-json`. Verdicts:

- **TP** — labeled positive and hard-fail
- **FN** — labeled positive and hard-pass
- **FP** — labeled control/sample and hard-fail
- **TN** — labeled control and hard-pass

Reports: `benchmarks/airflow/reports/latest.html` and `latest.json` (plus timestamped `run-*` folders).

## Independent validation

1. Open every PR URL in the HTML table.
2. Re-run discover + run with the same window/limits.
3. Compare `metrics` in `latest.json`.
